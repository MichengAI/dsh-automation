> DSH Automation — плагин для DeepSeek Harness (DSH), поддерживаемый сообществом, и не является официальным продуктом DeepSeek AI.

## Обзор возможностей

Доверьте повторяющиеся задачи DSH. Настраивайте задачи в параметрах или описывайте требования прямо в диалоге, а затем просматривайте результаты каждого запуска.

- **Однократный или регулярный запуск**: интервалы (в минутах), каждый час, ежедневно, еженедельно, ежемесячно или каждые N дней.
- **Гибкая рабочая среда**: настройка рабочей папки, модели, навыков и ограничений разрешений.
- **Управление расписанием в любое время**: создание, приостановка, возобновление, немедленный запуск и удаление задач.
- **Просмотр результатов**: доступ к сессиям по имени задачи и времени выполнения на вкладке **Расписание** или фильтрация истории в настройках.
- **Изолированные запуски**: каждый запуск использует сохраненную инструкцию и не наследует контекст диалога, в котором был создан.
- **Интерфейс на 8 языках**: русский, английский, китайский, японский, испанский, французский, немецкий и португальский, с поддержкой глобального языка DSH (требуется DSH `0.2.2-rc.1` или новее).

## Обзор интерфейса

Запланированные сессии отображаются как в официальном дереве **Задачи**, так и на вкладке **Расписание**. Неактивные сессии отмечены официальным значком часов. В разделе **Расписание → Записи** по умолчанию включена группировка по задачам, с возможностью переключения на группировку по рабочей области, дереву или плоскому списку. Режим рабочей области оставляет пространства видимыми и фильтрует только запланированные сессии; значок «+» в заголовке открывает создание задачи:

![Боковая панель расписания](assets/screenshots/workspace-scheduled.png)

Откройте **Настройки → Запланированные задачи**, чтобы находить, создавать, приостанавливать и просматривать правила:

![Настройки запланированных задач](assets/screenshots/settings-tasks.png)

Опишите задачу в чате. DSH запросит подтверждение в соответствии с выбранным режимом доступа:

![Создание задачи через чат](assets/screenshots/chat-create.png)

![Официальное подтверждение для automation_create](assets/screenshots/chat-approval.png)

После подтверждения правило сохраняется, а в диалоге выводится сводка:

![Запланированная задача создана](assets/screenshots/chat-created.png)

Журнал запусков хранится в настройках с возможностью фильтрации по дням, неделям, месяцам, задачам или статусам:

![Журнал запусков](assets/screenshots/settings-runs.png)

## Требования

- Совместимость с хостом: вся линейка DeepSeek Harness `0.2.x` (`>=0.2.0-rc.1 <0.3.0-0`), проверено на `0.2.0-rc.1`, `0.2.0-rc.2`, `0.2.1-rc.1`–`0.2.1-rc.5` и `0.2.2-rc.1`, с совместимостью со всеми последующими выпусками 0.2.x RC. Хосты на `0.1.x` должны оставаться на плагине `0.1.66`. Перед обновлением создайте резервную копию сессий и хранилища; `0.2.0` записывает сессии формата V4, которые не читаются при откате.
- Зависимости peerDependencies охватывают поколение `>=0.2.0-rc.1 <0.3.0-0`. Зависимости разработки зафиксированы на `0.2.2-rc.1`. Устаревшие версии и критические изменения `0.3.0` отклоняются фильтром версий. `@deepseek-ai/dsh-agent-presets` и `@deepseek-ai/dsh-agent-preset-registry` не являются пирами, а используют службу хоста `agentPresets`.
- Другие версии выходят за рамки заявленной совместимости.
- Плагин не переопределяет стандартную запись Connection хоста. Каждый хост сохраняет свои зависимости запуска и конфигурацию; автоматизация регистрирует свой RPC-канал в собственной области плагина.
- Работающая установка DeepSeek Harness Web с доступной командой `dsh` в PowerShell.
- Примеры используют профиль `web`; замените его на ваш рабочий профиль.
- Node.js 22.19+ для сборки из исходников или разработки. При обычной установке через npm выполнять локальный `npm install` не требуется.

## Установка

Приведенные команды используют официальный реестр npm.

### Установка с помощью агента (рекомендуется)

Отправьте следующую инструкцию любому агенту с доступом к терминалу (замените `web` на ваш профиль):

```text
Установи плагин DSH @michengai/dsh-automation в локальный профиль web: dsh plugin --profile web add @michengai/dsh-automation@latest --registry=https://registry.npmjs.org/. Затем выполни dsh --profile web --dump-config, убедись, что dsh-automation присутствует в конфигурации, и объясни, как перезапустить DSH и начать работу.
```

### Прямая установка через npm

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
dsh plugin --profile web add @michengai/dsh-automation@latest --registry=https://registry.npmjs.org/
dsh --profile web --dump-config
```

Перезапустите DSH Web и обновите страницу браузера (Ctrl+F5). Зафиксируйте версию с помощью `@0.1.5` вместо `@latest`, если это необходимо.
- **Работа за обратным прокси**: Поддерживаются префиксы путей (например, `/app/dsh/`). Запросы API разрешаются относительно `document.baseURI`.

## Настройки и переключатели плагина

Перейдите в:
> **Боковая панель → Плагины → Подробнее о `@michengai/dsh-automation`** (слот `plugins.bundle.config` хоста).

Доступны два нативных переключателя и выбор места отображения:

### 1. Элемент боковой панели (`sidebarEntry`)
- **По умолчанию**: Включено (`true`) / Бесшовный перенос при установке
- **Описание**: Отображает значок **Запланированные задачи** на панели действий.
- **Действие**:
  - **Широкая область 960px**: Открывает центр задач в удобном отцентрированном контейнере 960px, снимая ограничения тесных модальных окон.
  - **Корректная выгрузка**: При выключении аккуратно освобождает слот и переводит активный экран на стандартную сессию.
  - **Синхронизация в реальном времени**: Стандартное окно настроек и вкладки рабочего пространства всегда доступны и согласованы.

### 2. Скрыть официальный пункт автоматизации (`hideOfficialSchedule`)
- **По умолчанию**: Включено (`true`, согласовано с элементом боковой панели)
- **Описание**: Скрывает встроенный пункт хоста «Задачи автоматизации» (`ui-schedule`), предотвращая дублирование значков.
- **Действие**:
  - **Бесшовная замена**: Официальный пункт скрывается, уступая место полнофункциональному пункту плагина.
  - **Интеллектуальный возврат**: Если главный экран отображал расписание, он безопасно переключается на чат по умолчанию.
  - **Кэширование без мерцания**: Локальное хранилище устраняет мерцание значков даже при медленном соединении.
  - **Восстановление без следов**: Отключение или удаление плагина моментально восстанавливает официальный пункт.
  - **Безопасность обновлений**: Если пользователь ранее отключил `sidebarEntry`, официальный пункт остается видимым.

### 3. Показывать запланированные сессии в дереве задач (`taskTreeSessions`)
- **По умолчанию**: Выключено (`false`, скрывает запланированные сессии для поддержания чистоты)
- **Описание**: Управляет отображением запланированных запусков в общем дереве задач.
- **Действие**:
  - **Устранение шума**: Частые запуски изолируются от основного дерева, не перегружая рабочие проекты.
  - **Сохранность истории**: Все прошлые запуски всегда доступны для анализа в «Расписание → Записи».
  - **Легкий протокол**: Работает через контракт `NativeTabRegistry.sessionFilters` без нежелательных вмешательств в ядро.

### 4. Конфигурация в `cordis.patch.yml`
```yaml
- id: dsh-automation
  name: '@michengai/dsh-automation'
  config:
    stateDir: D:/Data/dsh-automation   # Опционально: каталог хранения настроек (по умолчанию в профиле)
    runTimeoutMinutes: 60              # Опционально: таймаут задачи в минутах (по умолчанию: 60, макс: 1440)
    misfireGraceMinutes: 15            # Опционально: окно допуска для пропущенных запусков (минуты)
    historyLimit: 200                  # Опционально: количество сохраняемых записей истории
    updater: false                     # Опционально: корпоративная блокировка обновлений (alias: onlineUpdate: false)
```

## Обновление

Встроенная кнопка проверки обновлений удалена. Для обновления повторно установите последнюю версию в тот же профиль командой `dsh plugin … add @latest`, перезапустите DSH и обновите браузер. В закрытых корпоративных сетях параметр `updater: false` или `onlineUpdate: false` в Cordis блокирует запросы на обновление ответом HTTP 403.

## Использование

Откройте **Настройки → Запланированные задачи**:

| Цель | Действие | Область |
| --- | --- | --- |
| Создать правило | Нажмите **Новая задача**, задайте имя, расписание, промпт, рабочую папку, модель и права | Весь хост |
| Создать через чат | Опишите расписание в диалоге или выберите **Создать в чате** | Текущий чат |
| Пауза / Возобновление | Используйте переключатель на карточке задачи | Одно правило |
| Запустить сейчас | В меню карточки выберите **Запустить сейчас** | Одно правило |
| Удалить | В меню карточки выберите **Удалить задачу** (история сохраняется) | Только правило |
| Просмотреть историю | Откройте **Журнал запусков** и отфильтруйте по дате или статусу | Весь хост |

Каждый запуск использует сохраненный промпт, рабочую папку, модель и границы прав, не переиспользуя разрешения из исходного чата.

Команды `automation_create` и `automation_update` поддерживают те же параметры модели, что и настройки (`provider`, `model`, `reasoning_effort`). При указании модели передавайте `provider` и `model` как пару непустых идентификаторов либо оба как `null` для следования глобальному выбору; неполные пары отклоняются.

## Границы безопасности

| Элемент | Поведение |
| --- | --- |
| Права доступа | Варианты и значения по умолчанию поступают напрямую из службы `permissionPresets` хоста. |
| Предустановки агента | Выбор из зарегистрированных пресетов `agentPresets`; карточки и история отображают фактически использованный профиль. |
| Вызовы инструментов | Строго следуют проверкам доступности, прав и утверждений хоста без жестких белых списков. |
| Полный доступ | Опция `danger-full-access` требует подтверждения риска с оранжевым предупреждением. |
| Подтверждения | Создание через чат следует политике сессии. Фоновые автономные запуски всегда безопасны (`never`). |
| Повторы | Без автоматических повторных попыток после старта выполнения. |
| Перезапуск хоста | Зависшие записи `queued` или `running` переводятся в статус `failed(host_interrupted)`. |
| Общая параллельность | Без искусственного глобального лимита плагина; параллельность регулируется для каждой задачи отдельно. |
| Минимальный интервал | С версии `0.1.40` интервалы принимают целые минуты от 1. При пропуске выполняется только самое актуальное срабатывание. |
| Лимит задачи | Настраиваемое число одновременных запусков (целое число, по умолчанию 1). При переполнении запуски получают статус `skipped(overlap)`. |
| Изоляция рабочей папки | По умолчанию привязана к рабочей папке исходной сессии. Изменения между папками требуют флага `cross_workspace: true`. |

Расписание фиксирует будущее намерение выполнения, а не кэшированное предоставление прав доступа.

## Разработка

### Установка из исходников

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
Set-Location D:\Repository\deepseek-harness-plugin
git clone https://github.com/MichengAI/dsh-automation.git
Set-Location .\dsh-automation
pnpm install
pnpm test
pnpm build
dsh plugin --profile web add .
dsh --profile web --dump-config
```

Перезапустите DSH Web и обновите браузер.
